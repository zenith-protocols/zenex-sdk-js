# Zenex SDK v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rewrite the TypeScript SDK for the v2 order->keeper-execute trading contracts and verify it live via zenex-utils on testnet.

**Architecture:** Hand-written contract bindings in the SDK's established style: `Contract` subclasses whose methods return base64 operation XDR strings, a static `contract.Spec` copied from `stellar contract bindings typescript` output, static `parsers`, and event decoder functions over `base_event.ts` normalizers. Clean break from v1; no compat layer.

**Tech Stack:** TypeScript, `@stellar/stellar-sdk` 14.x, vitest, stellar-cli, Rust/Soroban contracts as the source of truth.

**Spec:** `docs/superpowers/specs/2026-07-06-sdk-v2-design.md`

- Never use `--` or an em-dash in prose (docs, comments, commit messages). CLI flags are fine.
- All i128 contract fields are `bigint` in TS. u32/i32 are `number`, u64 is `bigint`.
- Follow the existing SDK code style: 4-space indent, single quotes, semicolons, `import ... from '...js'` ESM specifiers.
- Every field mirrored from a Rust struct keeps its unit note from the Rust doc comment (token-dec, price_scalar, SCALAR_18, seconds, ledger sequence).
- TDD per task: write the failing vitest test first, watch it fail, implement, watch it pass, commit. Conventional commit format, no attribution footer.
- Tests live in `test/` mirroring `src/` (e.g. `test/trading/trading_contract.test.ts`). Run with `npx vitest run <path>`.
- Struct -> ScVal maps: entries MUST be in alphabetical key order (Soroban ScMap ordering). Unit enums without discriminants (OrderKind, VaultOrderKind, Call variants) encode as `scvVec([scvSymbol('<Variant>')])`. `Status` has explicit discriminants and crosses the ABI as plain `u32`.
- The v1 trading surface (multi-market, placeLimit/openMarket-with-price, execute batch) is deleted, not deprecated.

```typescript
export function orderKindToScVal(kind: OrderKind): xdr.ScVal {
    return xdr.ScVal.scvVec([xdr.ScVal.scvSymbol(kind)]);
}

export function tradingConfigToScVal(config: TradingConfig): xdr.ScVal {
    const entry = (key: string, val: xdr.ScVal) =>
        new xdr.ScMapEntry({ key: xdr.ScVal.scvSymbol(key), val });
    const i128 = (v: bigint) => nativeToScVal(v, { type: 'i128' });
    const u64 = (v: bigint) => nativeToScVal(v, { type: 'u64' });
    return xdr.ScVal.scvMap([
        entry('adl_clear_target', i128(config.adlClearTarget)),
        entry('adl_max_pnl', i128(config.adlMaxPnl)),
        entry('borrow_rate', i128(config.borrowRate)),
        entry('deposit_lock', u64(config.depositLock)),
        // ... every remaining field, alphabetical by snake_case key;
        // notional_lock and redeem_lock are u64, the rest i128
    ]);
}
```
